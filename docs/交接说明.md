## 二、怎么跑起来

```powershell
# 浏览器版（改界面时用这个，热更快）
npm start                 # http://127.0.0.1:4173

# 桌面版开发（带热更新，走 vite dev server 1420）
npm run tauri dev

# 桌面版发布（产物 src-tauri\target\release\yijing.exe）
npm run tauri build -- --no-bundle

# 绿色便携版：应用 + 引擎装进同一目录，整目录可拷到别的机器
node scripts/package-portable.mjs

# 测试
node --test                            # 前端
cd src-tauri && cargo test             # 后端存储层
```

**整理后注意**：`src-tauri/target/` 里的 debug 构建缓存（6 GB）已被清掉，`target/release`
的依赖缓存保留，`yijing.exe` 仍在原位可直接双击。若换机器首次 `cargo build --release`，
需要重新编译全部依赖（数分钟）。

引擎在 `G:\Edge_download\KataGo`（TensorRT / CUDA）。路径按三级解析：环境变量
（`KATAGO_EXE` / `KATAGO_MODEL` / `KATAGO_CONFIG`，或只给 `KATAGO_DIR` 自动推导）→ exe 同目录的
`katago.json` → 默认安装位置；**相对路径以 exe 所在目录为基准**，便携版换盘符不失效。

## 三、这一轮做了什么

### 1. 试运行与体检 —— `aaf6beb` 之前

跑通了浏览器版与 10 局「当湖十局」真实棋谱，列出 7 个问题（导出丢座子、胜率标定不自洽、
Rust 后端与前端脱节、需求缺口、分析面板图表拥挤等）。其中两个致命问题在后续轮次修掉。

### 2. 古谱规则适配 —— `aaf6beb`

起因：你指出「古谱贴子规则和现在不一样，胜率图有待商榷」。复核后确认成立，且偏差很大——
当湖第 1 局第 40 手，按现代规则（贴 7.5 目）显示黑 0.5% / −19.1 目，光把贴目改成 0 就差 8 目。

明清规则三件事都补上了：座子（SGF 里本就有 `AB`/`AW`，但浏览器端 `server.js` 从没把
`initialStones` 传给引擎，等于一直在**空盘面**上分析古谱——顺手修掉）、白先、无贴目。
**还棋头 KataGo 不支持**（分析查询里 `taxRule`/`tax` 都被 `Unexpected or unused field` 拒掉），
所以由前端按「除第一块外每块 2 目」计算，**只在终局算一次并单独标注，不混进逐手曲线**。
十局实测修正量 +22 / +20 / −14 / +4 / +8 / +4 / −12 / +10 / −4 / −10 目，平均约 10.8 目，
量级与贴目相当，足以改变胜负判断。

### 3. 界面重做：棋盘优先的四层递进 —— `372d78b`

旧布局在 1440×900 上同时有侧栏(230)+顶栏(70)+棋谱栏(310)+AI 栏(335) 四层 chrome，
棋盘被挤到 520px。重写成四层：

1. **棋盘层** —— 始终在，占满视口（87.6% 高）
2. **悬浮层** —— 对局信息、工具轨、播放条浮在棋盘上，静止 4.2s 淡到 13%
3. **抽屉层** —— 棋谱库 / AI / 走势，默认浮在棋盘之上，点「⇥」固定后变并排、棋盘让位
4. **专注层** —— `F` 或 ⛶，全隐藏 + 真全屏（棋盘 97% 视口高）

用 `ui-layers.js` 对 8 个状态做数值断言：**棋盘与悬浮件的遮挡面积全部为 0**。这套断言抓出
三个肉眼看不见的问题（工具轨压住面板 12px、两面板并排时棋盘被压到 324px、窄屏播放条重叠 25px）。

### 4. 标记体系与音效 —— `a9a07b6`

三类标记按字形分开，不再看混：**数字**＝手数（当前手用强调色）、**红圈**＝当前手外圈
（关掉手数也保留，这是「找得到实际着棋点」的关键）、**字母 A/B/C + 空心圈**＝ AI 候选。
`手数`/`AI 点` 变成可开关显示项，状态落 `localStorage`，工具轨按钮/设置弹窗/快捷键三处同步。
音效从单振荡器（像电子提示音）改为「噪声瞬态 + 带通谐振 + 低频托底」合成，落子清脆、
提子是数颗子连击。

### 5. 转成本机桌面应用 —— `571a9a1`

`analyze_position` 由同步命令改 `async` + `spawn_blocking`（模型加载 30–90 秒会冻窗口），
stdout 交给独立线程按请求 id 派发、每请求自带超时。补 `library_load`/`library_save`/
`open_data_folder`/`set_window_title`/`log_line`/`warmup_engine` 等命令，窗口销毁时回收
KataGo 进程（否则 Windows 上留下占显存的 `katago.exe`）。

**最耗时的一环是白屏排查**：窗口正常、标题正确、进程活着，客户区整片空白、JS 完全不执行。
逐项排除了资源缺失（资产解析器能返回全部文件）、路由（URL 确实是 `http://tauri.localhost/`）、
CSP、WebView2 运行时缺失，最后定位到 `additionalBrowserArgs` 缺 `--no-sandbox --disable-gpu`。
**这两个参数别删**，理由见 README。

### 6. 收掉两个遗留 —— `6f95ff3`

- **导出 SGF 丢座子**：序列化统一移进 `core.js` 的 `serializeSgf()`（可单测），写回
  `AB`/`AW`/`HA`/`KM`/`RU`/`SZ`/`PL`。桌面版不走 `<a download>`，改 Rust `export_sgf`
  落盘到「下载」目录并回报完整路径。
- **棋谱库改走 SQLite**：旧做法是整个库序列化成一个 `library.json` 覆盖写，改一个收藏也要
  重写全库。新结构一局一行（`payload` 存整份 JSON 保证字段零损失、`digest` 做增量比对），
  前端用「影子表」比对内存状态得出差异后只提交变过的部分。顺带删掉 Rust 里三张从没用过的
  空表（folders/games/game_search）和 5 个对不上界面模型的老命令。
- **顺手修**：关窗时丢改动（`saveLibrary` 有 250ms 防抖但没有 flush，正好在窗口里点 X 那一下
  改动会随进程消失）→ 用 `onCloseRequested` 拦下、等落盘再关。

## 五、几个关键决策及理由（别人问起时用得上）

- **还棋头不进逐手曲线**：它是终局结算量，混进逐手胜率会让曲线出现凭空的跳变。
- **不接 FTS5**：界面搜索是「棋谱名/对局者/赛事/标签」的**子串**匹配（`当湖` 要命中「当湖十局」），
  FTS5 默认分词器把整串中文当一个词元，换上去反而搜不到；且每敲一键一次 IPC 比内存过滤更慢。
  真正的瓶颈是「全量载入内存」，那是另一件事（见第八节）。
- **棋谱主键由数据库交回前端**：Rust 的 `serde_json` 与 JS 的 `JSON.stringify` 对浮点数的文本形式
  可能不一致，两边各自推算主键会对不上，结果是**写成重复行而不是更新**。改为 `library_load`
  返回与 `games` 对齐的 `keys`，前端沿用数据库原文。
- **座子不写成 `HA`（让子）**：座子制是双方各摆两子的固定开局，标成让子会让别的程序误读成让子棋。
  只在白方无摆子且黑方 ≥2 子时才写 `HA`。
- **按钮文字标签不能省**：悬浮层静止 4.2s 会淡出，最初工具轨只有图标，用户根本没找到，补了 `<em>` 文字。

## 六、改代码前必读的坑

1. **WebView2 参数不可省**：`--no-sandbox --disable-gpu` 缺任一，在远程桌面/虚拟机/受限会话下
   表现就是「窗口正常、客户区空白」。该字段会**整体覆盖** wry 默认值，所以要自己补上
   `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`。
2. **关窗用 `core:window:allow-destroy`，不是 `allow-close`**：Tauri 的 `onCloseRequested` 包装是
   `await handler(event); event.isPreventDefault() || await this.destroy()`。用 `close()` 收尾会再发
   一次关闭请求绕回原处，而 `allow-destroy` 未授权时**窗口根本关不掉**。
3. **SGF 没有 `\n` 转义**：规范里 `\` 只转义下一个字符，`\` + 真换行是软换行。把换行写成 `\n`
   会让规范解析器还原出字母 `n`。换行原样写，只归一 CRLF；坐标对不跳过字母 `i`。
4. **同一文件别并行编辑**：同一轮对同一文件发多个编辑，会有一次被静默吞掉却仍报成功。
   串行提交，改完 grep 关键串自检。
5. **顶层解构 `const {...} = window.YijingCore` 缺键不报错**，直到调用时才炸，报错行号指向调用处，
   容易误导成「core.js 有问题」。
6. **别用日志判断数据是否落盘**：`desktopLog` 是异步 fire-and-forget，紧接 `destroy()` 时会丢，
   直接查库内容。
7. **本机 Bash 工具 PATH 损坏**：每条命令前先 `export PATH="/c/Windows/System32:/c/Windows:/usr/bin:/bin:/c/Program Files/nodejs:$PATH"`，
   涉及 cargo 再加 `/c/Users/见/.cargo/bin`。
8. **构建偶尔 `failed to build app`**：先 `taskkill /IM yijing.exe /F` 再重跑（残留进程占文件锁）。

`.workbuddy/memory/2026-09-17.md`——这两份是除本文档外最详细的现场记录，建议一并读。

## 八、已知遗留与下一步

按优先级：

1. **棋谱全量载入内存** —— 棋谱上万时需要改按需加载，这是当前真正的性能天花板。
2. **`library.json.imported-*` 留档文件不自动清理** —— 目前靠用户自己删。
3. **写改动的入口必须走 `saveLibrary()`** —— 它靠影子表比对内存状态得差异，绕过它就静默丢改动。
4. 需求 3、5、7 的未实现部分：分支变化、评论、圆圈/三角/文字标记、删除/插入着法、热力图、
   跨对局统计报表（见 `需求清单.md`）。
5. 两个面板同时固定时棋盘只剩 608px（1440 屏），是「两个 320px 面板 + 工具轨」的必然结果，
   要更好只能在窄屏上改单列或取消同时固定。
